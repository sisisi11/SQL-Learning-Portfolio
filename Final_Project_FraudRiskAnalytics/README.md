# Fraud Detection & Transaction Risk Analytics

## Overview

This is a **personal SQL portfolio project** built with Microsoft SQL Server / T-SQL.

The project simulates a simplified transaction-monitoring environment and demonstrates how SQL can be used to:

- model customer and transaction data;
- analyse customer behaviour;
- detect suspicious transaction patterns;
- calculate risk indicators;
- generate fraud alerts;
- prepare data for investigation and reporting.

All data is **synthetic**. The project demonstrates SQL and analytical capability — it does **not** represent professional banking or fraud-investigation experience.

---

## Why this project

I wanted to build something that goes beyond basic `SELECT`, `JOIN`, and `GROUP BY` statements.

The project focuses on a realistic analytical problem: turning raw transaction data into useful risk signals.

It combines database design, analytical SQL, business logic, performance considerations and investigation workflows.

## Main objects

### `Customers`
Stores customer profile and baseline risk tier.

### `CustomerDevices`
Tracks devices associated with customers and whether a device is trusted.

### `Transactions`
Stores transaction-level data including amount, timestamp, country, channel and device.

### `FraudAlerts`
Stores alerts generated by different risk rules.

---

## Interesting analytical examples

### 1. Velocity detection
Detects customers with multiple transactions occurring in a short period.

### 2. Rapid sequence analysis
Uses `LAG()` to compare each transaction with the previous transaction for the same customer.

### 3. Device / country switching
Uses window functions to identify changes in device or country within a short time interval.

### 4. Amount anomaly analysis
Calculates a customer-level average and standard deviation, then derives a Z-score-like indicator.

### 5. Risk scoring
Combines multiple indicators — transaction behaviour, number of devices, countries, decline count and customer risk tier — into a numerical risk score.

### 6. Investigation procedure
`usp_InvestigateCustomer` produces a compact customer investigation package:
- customer risk summary;
- transaction timeline;
- fraud alerts.

## How to run

1. Install SQL Server Developer Edition or use an existing SQL Server instance.
2. Open SQL Server Management Studio (SSMS) or Azure Data Studio.
3. Open `FraudRiskAnalytics.sql`.
4. Execute the script from top to bottom.
5. Run individual analysis sections separately and inspect the results.

## What I would improve in a production version

A production system would need much more than this demonstration project, including:

- rule configuration tables instead of hard-coded thresholds;
- historical baselines calculated only from data available before each transaction;
- currency normalization;
- merchant risk profiles;
- geo-distance / impossible-travel detection;
- IP reputation;
- stronger alert deduplication;
- auditing;
- incremental processing;
- data partitioning;
- security and access controls;
- performance testing on millions of rows.
